# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Read first

`DESIGN.md` is the authority on intent (architecture, data model, §13 milestones with exit criteria). `README.md` describes current behaviour. **Both are deliberately kept current — a change that alters behaviour updates them in the same commit**, including the test count in the README.

Python 3.12+. Windows is the primary dev platform; commands below use the repo-local venv.

## Commands

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"   # installs okflint + pytest + the MCP SDK

.\.venv\Scripts\okragged doctor          # both providers (synth + embeddings), credentials, reachability
.\.venv\Scripts\okragged build --dry-run # discover + extract only; no model calls, no writes
.\.venv\Scripts\okragged build           # full pipeline -> bundle/ + okf-base.yaml
.\.venv\Scripts\okragged index           # embed + project + graph.json -> .okragged/ only
.\.venv\Scripts\okragged serve           # read-only API + the graph view (needs the api extra)
.\.venv\Scripts\okragged check           # validate an existing bundle without rebuilding
.\.venv\Scripts\okragged agent           # regenerate agent/AGENTS.md (offline)
.\.venv\Scripts\okragged agent --register # also register the server in .mcp.json
.\.venv\Scripts\okragged agent --register --write --spend  # ... as a writing, spending instance
.\.venv\Scripts\okragged mcp             # serve a bundle over stdio, read-only; --project
.\.venv\Scripts\okragged mcp --write --spend  # ... offering add_source, on your credential
.\.venv\Scripts\okragged extract <file>  # print extracted text for one file (offline)
```

Tests — okflint is resolved beside the interpreter, so `PATH` no longer decides whether the okflint-dependent tests run:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q              # 391 tests, none skipped
.\.venv\Scripts\python.exe -m pytest tests/test_segment.py -q
.\.venv\Scripts\python.exe -m pytest tests -q -k "footnote"
```

No credentials and no network are needed for the suite; the end-to-end test stubs the model.

## Architecture

Three layers plus a sidecar (`DESIGN.md` §2):

| | Directory | Owner | Notes |
|---|---|---|---|
| 1 raw sources | `sources/` | user | immutable; okragged reads, never writes |
| 2 the bundle | `bundle/` | okragged | the OKF v0.2 product |
| 3 agent contract | `agent/` | okragged | generated: `AGENTS.md`; the server is `okragged mcp`, registered on request into `.mcp.json` |
| sidecar | `.okragged/` | okragged | derived, disposable |

**The sidecar rule is the load-bearing constraint: nothing derived ever goes inside `bundle/`.** The ledger (`manifest.json`), the extraction cache, proposed replacements for concepts a human owns, and later embeddings/index/projection all live in `.okragged/`. A bundle must stay something you can `tar` up and `cat` with no knowledge of okragged — no `embedding:` frontmatter key, no `.faiss` file.

Pipeline (`pipeline.py::ingest`): `discover → extract → plan → synthesize → link-weave → emit → validate`, **under the project lock, committing one source at a time** — `ingest` holds `.okragged/lock.json`, every write goes into `.okragged/staging/bundle/`, and one fenced commit per source publishes its concepts, removes the stale output its rename left behind, and moves the ledger describing it into place (`lock.py`, `staging.py`, `DESIGN.md` §6.6). Then, as a separate command, `vectors.index`: `embed → project → graph`. `ingest` also takes a `progress` callback (`Progress`, one event per stage per unit) — the events `POST /api/ingest` was waiting on (§11).

**The layer-3 contract is regenerated after the commit, and registration is not part of it.** After, never before: a contract written beside a bundle that did not land describes one that does not exist. `ingest(contract=...)` defaults to on for *every* caller, CLI and library alike — §10 depends on `agent/AGENTS.md` never describing a bundle that no longer exists, and a run that committed is the moment the bundle changed.

**The two layer-3 artifacts have different natures, which is why two functions write them.** `AGENTS.md` is a function of the bundle — concept count, structure tree, type vocabulary — so it is rewritten whenever the bundle changes. `.mcp.json` is a function of *nothing*: since M5 the entry is `{"command": "okragged", "args": ["mcp"]}`, the same bytes at no concepts and at a thousand. Under M4 it named the generating interpreter and the generated `agent/mcp_server.py` and really was derived from this tree; the console script deleted that, and the rewrite-on-every-build outlived its reason. So `write_contract()` writes `AGENTS.md` and `register()` writes `.mcp.json`, the latter only from `okragged agent --register` or an explicit call. **The one thing the entry is still a function of is the machine**: a client spawns the server from `.mcp.json` rather than from an activated shell, so `register()` writes the bare `okragged` when `shutil.which` resolves it and the console script beside `sys.executable` when it does not — the same exposure as `_okflint`, with a worse symptom (a lost server reported as `CONNECTION_CLOSED`, not a degraded check). `PATH` first rather than beside-first, because this file is not gitignored and a bare name is the only one that travels. **`--register` also accepts `--write` and `--spend`, which land in the entry's `args`** — an operator typing `okragged agent --register --write --spend` is asking for precisely that entry, so nothing is inferred; omitted, the entry stays bare and the server it spawns is read-only, and that default does not move. Two things this must not break, and there is a test for each: **`is_registered` matches the server key rather than the argument vector**, or a flagged entry reads as unregistered and every build tells the operator to register a server that is already there; and **the entry `AGENTS.md` hands a *foreign* project stays bare unconditionally**, because this machine's authorization is not a fact about another machine's and a snippet shipping `--spend` would be telling a stranger to spend a key — the contract says so in prose beside the flagless JSON. **Nothing writes `.mcp.json` on a caller's behalf** — it is the machine's MCP config, shared with every other server registered in it, and the one file here okragged does not own. A build only *mentions* that the server is unregistered. The reasoning lives in `agent/contract.py`, where the two part company.

**In `build`, only synthesis and link-weave call a model.** `check`, `extract`, and `build --dry-run` are entirely offline, and `build` fails its credential pre-flight *before* extracting the corpus rather than after. `index` calls an *embedding* provider, configured separately in `[vectors]`, and `build` never calls it — nothing in the build path uses a vector.

Module responsibilities:

- `__init__.py` — the public Python API (`DESIGN.md` §13 M5 item 3), and **nothing but re-exports**: ten functions that resolve `str | Path | Config` and delegate to the function the CLI calls, plus `Config` and `Progress`. The capability was never missing — every module has always been importable — so this earns its place only by staying thinner than reaching into the submodules. No new return types, no `Bundle` (§2: a bundle is a directory), no `provider=` in any signature, and no `load_dotenv`: credential discovery belongs to the entry points humans use. **Every import in it is deferred** — function-local, plus a module `__getattr__` (PEP 562) for the two names — because `markitdown` prints an ffmpeg warning when imported and `extract/` imports it, and a library whose import writes to somebody else's stderr is broken. `tests/test_library.py` asserts the import prints nothing and pulls in neither the extraction path nor a provider; keep new public names out of the module body.
- `okf/` — the format layer, and the only part with standalone value (M10 candidate). Bound to the OKF spec, contains no model call. **Keep it free of any dependency on `synth/`, `pipeline.py`, `vectors/` or `agent/`.**
- `synth/` — provider dispatch. Everything shared (prompt assembly, JSON parse, required-field checks, footnote repair) lives in `synth/__init__.py` and `synth/base.py` so the provider paths cannot drift. **The footnote repair has two halves and `body_defines` is why**: `ensure_footnote_defs` appends a definition that was never written, and `anchor_footnote_defs` breaks the line before one the model left mid-line, which renders as literal text rather than as a footnote. `body_defines` is line-anchored like `FOOTNOTE_DEF_RE`, because a substring check accepted the mid-line case as defined and the repair for it never fired. **`weave.py` applies the anchor too** — it rewrites the body, so a definition it inlines is its own to fix, and it is the only pass that runs after the one that appended it. Provider modules stay thin: auth, request shape, decline detection.
- `sources/base.py` — the `Source` protocol with its `document` vs `asset` family split; phase-2 connectors plug in here.
- `pipeline.py` — orchestration only; assembles `Concept` objects from synthesis results.
- `ledger.py` — the idempotency ledger, `.okragged/manifest.json`. Sidecar state, so every read path degrades to "no record" rather than raising. **Not `okf/manifest.py`**, which generates `okf-base.yaml` for okflint.
- `lock.py` — one writer per project, `.okragged/lock.json` (`DESIGN.md` §13 M5 item 6). Exclusive creation, because `fcntl` is not available on the primary platform, plus the record and the liveness probe that let a *dead* holder's lock be reclaimed with no human in the loop. Never `os.kill(pid, 0)` — on Windows that terminates the process it asks about. **No read path takes it**, and neither does `build --dry-run`.
- `staging.py` — the per-source commit, its pending-commit record, and the replay. Knows about `bundle/`, the ledger and the format layer but nothing about synthesis; `okf/` must not depend on it any more than it depends on `synth/`. The claim it makes is *recoverable*, not atomic, and the docstring says why atomic is not on offer — and why the **source** is the unit.
- `agent/` — layer 3 (`DESIGN.md` §10): `query.py` (`search`, `read_concept`), `lint.py`, `contract.py` (`write_contract` generates `agent/AGENTS.md`; `register` writes the `.mcp.json` entry and is never called for you) and `server.py` (the four MCP tools plus the two resources, served by `okragged mcp`) and `write.py` (`add_source`). **Nothing the server says over the wire may name a path relative to the producer's root** — the consumer works in another tree, which is why the contract is a resource rather than a file to open, and `tests/test_agent.py` enforces it. **`ingest` is deliberately not on this surface** — a full sweep deprecates every concept when `sources/` is absent but the ledger is not, so the branch is unreachable over the protocol rather than guarded on it. Whole-corpus synthesis is `okragged build`. **The load-bearing rules live in the tool descriptions**, because `instructions` is client-dependent and resources are an optional client capability, but a tool's description is shown wherever the tool is. `server.py` imports the MCP SDK lazily — it is an optional extra — and `agent/__init__.py` deliberately does not import it, because `pipeline.py` imports this package.
- **What this surface may spend is a property of the instance, and both switches default to off** (`DESIGN.md` §10, §13 M6 items 2, 4, 5). `okragged mcp` is read-only and reads no `.env`; `--write` registers `add_source`; `--spend` reads the credential, which is what turns `add_source` into the one that also authors and embeds the concept. Neither takes an `envvar`, where `--project` does — a mode a stray variable could turn on is the ambient authority this removed. A read-only instance **omits** the writing tool rather than offering one that refuses, and the two `add_source` variants are separate registrations with separate descriptions, because the description is the only channel every client shows a model and it has to be true of *this* instance. What stands behind the spending mode is only that the operator invoked it: no identity, no scope, no rate limit, which holds while the caller and the payer are the same person and stops holding when there is somebody else on the far end (§13 M8).
- **`write.py` reports; it does not raise after the file is written.** The prose is in the corpus by then, so a missing `[synth]` credential, a lock another writer holds, and a failure to embed all come back in `errors` with `synthesized`/`indexed` saying what happened. A synthesizing call refreshes the vectors (`vectors.index`) **after** `ingest` has released the lock, never inside it — `hold` is not reentrant. And the two credentials behind `--spend` are not interchangeable: `[vectors]` embeds, `[synth]` synthesizes, both gemini modules read `GEMINI_API_KEY`, so a message that said only "no credential" would send the caller to the wrong key.
- **`search` may not hide a concept, and `note` is how it says so.** Its two fallbacks describe the embedding path being *unavailable*; a stored matrix that exists but does not cover every concept matched neither, so a concept written since the last `okragged index` was silently not a candidate and `note` came back empty — worse than an error, because the caller concludes the bundle does not answer. The uncovered concepts are now ranked by traversal and merged in, `path` has a third value, and the two rankings are **alternated by rank rather than sorted together**: a cosine similarity and a term-overlap score are different quantities. `note` is empty only when the ranking saw everything.
- `api/` — the read-only HTTP half of layer 3 (`DESIGN.md` §11), behind `okragged serve`. Four endpoints, all offline, **none of which writes anywhere**. `search` and `lint` call the same functions `agent/` exposes over MCP rather than reimplementing them, so the view and an agent cannot be told different things about one bundle — preserve that when adding an endpoint. FastAPI is an optional extra imported inside `create_app`, so importing the package costs nothing without it. The two ingest endpoints of §11 are deliberately deferred.
- `web/` — the sigma.js view (Vite + React + TS). Positions come precomputed from `graph.json`; sigma is a renderer, never a layout engine. `web/src/encoding.ts` holds §8's visual encoding alone, so the legend and the renderer cannot drift. Filtering lives in sigma reducers rather than in graph rebuilds, or the τ slider reloads the graph on every pixel.
- `vectors/` — embed, project, kNN, `graph.json`. Writes only into `.okragged/`, and `okf/` must not depend on it any more than it depends on `synth/`. `vectors/providers/` mirrors `synth/providers/` module for module; which embedding provider is right is **an open question** (`DESIGN.md` §12 Risk 4) and both registered ones stay registered until a real corpus answers it.

Adding a provider means one module under `synth/providers/` exposing `NAME`, `DEFAULT_MODEL`, `ENV_VARS`, `credential_present()`, `list_models()`, `call()`, registered in `providers/__init__.py::PROVIDERS`. Both current providers enforce the concept schema natively (Anthropic `output_config.format`, Gemini `response_json_schema`) — output shape is guaranteed, never parsed out of prose.

## Invariants that are easy to break

**Encoding.** Windows defaults to cp1252, and five separate M1 bugs came from trusting a platform default at an I/O boundary. Reads use `encoding="utf-8-sig"`, writes use `encoding="utf-8", newline="\n"`, subprocesses decode `utf-8`/`errors="replace"` *and* set `PYTHONIOENCODING=utf-8` in the child's `env`. **`tests/test_encoding.py` enforces this by walking the AST of everything under `src/okragged/` — a deviating call site fails the suite.** README's *Encoding policy* table is the full rule set.

**Executables are resolved beside `sys.executable` before `PATH`.** `okf/validate.py::_okflint` does this, and the reason generalises: the MCP server is spawned by its `.mcp.json` entry rather than from an activated shell, so a console script installed into okragged's own venv is invisible to `shutil.which`. The symptom was silent and asymmetric — `lint` told an agent "okflint not installed" while `okragged check` in a terminal ran it, so the same bundle was validated to two different standards depending on who asked. Any future subprocess okragged owns has the same exposure.

**The version is declared once, in `pyproject.toml`.** `okragged.__version__` reads it from package metadata and `[bundle].actor` defaults to `okragged/{that}`. The third copy is the one that mattered: `actor` is stamped into every concept's `generated.by`, so a hand-kept string that missed a release would misattribute provenance inside the bundle rather than merely misreport the tool. Both reads are lazy, because `__init__.py` defers every import.

**A staged file is fsynced, not just its record.** `staging` publishes on the strength of a pending record it fsyncs; `okf/writer._atomic_write` and `Ledger.save` therefore fsync too, or the record could outlive the content it names and the replay would place a truncated concept. `Ledger.save` is also temp-file-plus-rename rather than a plain write, because a half-written ledger loads as an empty one and an empty ledger re-ingests the corpus.

**Nothing okragged serves may resolve a path inside the user's project that only the producer's tree has.** `api.app.STATIC_DIR` is `Path(__file__).parent / "static"` — package-relative — after being `project_root / "web/dist"`, which put the built frontend inside whatever corpus `okragged serve` was pointed at. Vite's `outDir` writes there and the wheel ships it as an artifact. This is the same rule as the MCP server's, one layer down.

**`verified` is never written.** It records a confirmation event that actually happened; writing it because content looks correct forges the human-reviewed trust tier. Concepts are emitted `status: draft` and a human promotes them by editing the file.

**System prompts must stay byte-identical across a run** (`synth/prompt.py`), or Anthropic prompt caching stops working. Section framing goes in the user message, never the system prefix. The concept index in the prefix is snapshotted *before* discovery for the same reason — letting it grow as concepts land would be more informative and would stop it caching after the first unit.

**The commit boundary is the source, and the ledger never outruns the bundle.** One source's emit is staged (`staging.py`, `DESIGN.md` §6.6) and published by one fenced commit: the concepts it wrote under their new ids, the removal of the stale output its rename left behind, and its own ledger entry — together or not at all. That is the window worth fencing, because concept ids come from model-written titles: half of *one source's* emit is not a partially updated tree, it is a mix of two namings, and stale-output cleanup reconciles against a complete emit. Across sources there is nothing to fence — source A's new concepts beside source B's untouched old ones is a valid bundle — which is why fencing the whole run was the wrong trade. **The half that cannot be relaxed** is the direction: a source recorded in the ledger must be a source whose concepts are published, or the next run's content-hash skip believes work was done that was not and the corpus loses sources silently. The other direction only costs a re-synthesis. A crash mid-commit is finished by the next run when the pending record is there and rolled back when it is not; either way the next run *reports* what it found. Anything new that publishes into `bundle/` goes through the same commit, and anything that writes into the sidecar takes the lock.

**Per-unit failures never abort a run, and an interrupted run keeps what it published.** A refusal, a token-cap stop, or any non-2xx becomes an error recorded against that file or section; the sections that did synthesize are kept. Because the commit boundary is the source, an interrupt loses only the source in flight: every source before it is published *and* recorded, so the next run pays for the remainder and nothing else. Its staged files wait in `.okragged/staging/` until the next run reports and clears them, and the extraction cache survives, so even that re-payment is model calls and not extraction. `_finalize` (indexes, log, okflint manifest) runs in a `finally` — and those three are **derived from the bundle on disk**, not accumulated, so a run that dies before them leaves them stale and any later run regenerates them. **The ledger is deliberately not in `_finalize`**: it lands with the source it describes, and saving it on the way out could describe a concept whose file never landed.

Two asymmetries to keep. A failed **section** marks the source `complete: false` in the ledger so the next run retries it, because that is source content missing from the bundle; a failed **weave** does not, because the concept is valid and only its links are missing. And an interrupt *before* link-weave must land in exactly that failed-weave state — a published, valid, link-less concept, recorded consistently, `complete: true` — rather than in a new one of its own. Link-weave runs after every source has committed, so it overwrites published concepts, and each rewrite commits with its own re-noted hash: a body and a hash that disagree is read as a human edit (§6.4), which would protect the concept from every later run.

**One model call per unit, each with its own `max_tokens`.** A single call returning an array makes every concept share one budget — that is what capped M1 at ~2.5k per concept regardless of source length.

**New `type` values are reported, never silently accepted.** They surface in the build summary for the owner to add to `okragged.toml`.

**Broken cross-links are warnings (`W2`), not errors.** The spec permits pointing at knowledge not yet written — *by a human*. The link-weave pass is handed the full concept index, so a path outside it is a guess, and `synth/weave.py::prune_links` unwraps it and reports the target. Two other model link errors are repaired there too (inverted syntax, a raw path used as the label). Repairs go in `prune_links`, not in the prompt: a repair is checkable offline, a prompt rule is not.

**`okf-base.yaml` is deliberately minimal** — no `profile` block (it would reject newly proposed types) and no `okf_version` key (okflint 0.3.1 recognises only `0.1`). `okf/manifest.py` documents why each key is present or omitted. Note this is the *okflint* manifest; the idempotency ledger (`.okragged/manifest.json`, `DESIGN.md` §5) is a different artifact and lives in `ledger.py`.

**`bundle/`, `sources/`, `.okragged/`, `agent/`, `okf-base.yaml` and `.env` are all gitignored** — and so is `.claude/worktrees/`, a nested checkout git would otherwise record as a gitlink. Concept ids derive from model-written titles, so every rebuild renames the whole tree and the diff is unreadable; a bundle worth showing goes under `examples/`, refreshed deliberately. `agent/` goes with it: `AGENTS.md` is generated from the bundle and carries the corpus's own names. **`.mcp.json` is deliberately not ignored** — it is the machine's MCP config rather than okragged output, written only when asked, so whether it belongs in a history is the owner's call and not this tool's.

## Current state

M1 and M2 done — all four M2 items (segmentation, incremental re-ingest, link-weave, per-directory indexes), verified on the real corpus: conformant bundle, okflint exit 0, and a second `build` making zero model calls.

**M3 is done** — `embed`, `project` and `graph.json` behind `okragged index`, the four read endpoints behind `okragged serve`, and the sigma.js view in `web/`. See `DESIGN.md` §13, which lists M3 before M4 because that is the order the work happened in, not because the reason for the original swap stopped holding.

**τ has met a corpus and the default lost, which is the milestone's real output.** On the 18-concept Spanish corpus the median similarity over all 153 pairs is 0.896 and 150 of them clear τ = 0.82 — the 76 ghost edges are 76 because `knn_k = 8` capped them, not because τ discriminated. **The default has deliberately not been changed:** one saturated single-topic corpus rules 0.82 out without distinguishing "raise τ" from "lower k" from "make the threshold relative to the corpus", and fitting a constant to one sample is how a guess becomes a number nobody can argue with. Risk 1 in §12 records this. A second, less homogeneous corpus is what moves it.

**M4 (agent contract) is done** — `src/okragged/agent/`, generated on every build and by `okragged agent`. Its exit criterion was met against the real corpus over a real stdio session with no embedding credential: `search` answered by traversal, `read_concept` returned the concept whole, `lint` reported okflint exit 0. Now that `okragged index` has run, `search` takes the embedding path on this corpus and the traversal fallback is exercised only by the tests — **keep it that way; it is the path the exit criterion depends on.**

**M5 (distribution) is in progress.** The package, the module and the console script are all `okragged` (`ragged` on PyPI is taken), and **layer 3 now crosses the process boundary over the protocol rather than over the filesystem**: the server is `okragged mcp --project <dir>`, `.mcp.json` registers a console script with no interpreter path and no script path, the generated `agent/mcp_server.py` is gone, and `okragged://contract` / `okragged://index` serve the contract to a consumer that cannot see this tree. Verified over a real stdio session spawned from a foreign cwd. `add_source` has replaced `ingest` on the tool surface, and **the Python API is built** (`src/okragged/__init__.py`) — with the two behaviour changes that made it honest: `_finalize` no longer writes layer 3 unasked, and `ingest` reports progress while it runs.

**Layer 3 has since been split in two, and registration left the build path.** `AGENTS.md` is derived from the bundle and is still regenerated after every commit; `.mcp.json` is not derived from anything and is now written only by `okragged agent --register` or `okragged.register()`. That also collapsed the library-versus-CLI asymmetry — `okragged.build()` defaults `contract=True` like the CLI, because the surprise the old default guarded against was `.mcp.json` specifically, and a build no longer writes it either way.

**All six M5 pieces are now built, item 6 last: the lock and the staged emit** (`lock.py`, `staging.py`, `DESIGN.md` §5, §6.6). One writer per project, an emit that stages and then commits behind a pending-commit record, and a ledger that lands with the source it describes or not at all. The claim is *recoverable*, not atomic — no filesystem call publishes several files at once on Windows and the design says so rather than implying otherwise. **Item 6 shipped whole-run first and the boundary has since moved to the source**, because the hazard it fences lives inside one source's emit while a whole-run fence additionally threw away every source an interrupted run had paid for. What is left in M5 is the exit criterion itself, which is a session from a checkout that is not the producer's; nobody has been that consumer yet.

**M6 has three of its five items — 2, 4 and 5 — and its exit criterion is open.** `okragged mcp` is read-only unless asked otherwise, reads no `.env` unless asked, and offers a synthesizing `add_source` to an instance whose operator is the one paying. The identity and the spend scope (items 1 and 3) are **deliberately not built**: an identity the caller supplies is not an identity when the caller owns the process, the files and the environment, and a rate-limit counter in `.okragged/` is a counter he can delete. They bind where there is a channel and a host holding the only key, which is M8. **Two defects found by driving it rather than by reading it** are worth remembering as a method: a fresh agent asked to answer from a concept the protocol had just written could not, because `search` was blind to a concept with no vector and said nothing; and the contract, being a function of the bundle, was still asserting that nothing here spends a credential. Both are fixed (§10) — the second by describing the modes instead of asserting one, which is the only thing a file that cannot know how the server was started may do.

**Prompt calibration was deferred until after M2** (§13) and is now unblocked. Few-shot examples are the strongest signal in a prompt, and writing them before segmentation settled would have baked in guesses about the unit shape. The method is to take a concept a human promoted from `draft` to `stable` and use *that* as the example — so it needs a human to promote one first. Until then, don't "improve" prompt wording opportunistically; a model failure that can be repaired deterministically (see `prune_links`) should be, because a repair is testable and a prompt rule is not.

## Tests

Behavioural test names (`test_a_bom_in_a_concept_does_not_read_as_missing_frontmatter`), model always stubbed, no network. `tests/test_encoding.py` includes a meta-test pointing the AST check at a deliberately bad file — a guard that always passes guards nothing. Follow both conventions.
